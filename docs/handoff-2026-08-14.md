## 4. Session-process notes (learned the hard way)

- **Subagents sometimes return EMPTY or get interrupted mid-work.** Recovery:
  check `git status`/`git diff --stat` FIRST (partial work often exists and
  compiles), then re-dispatch with a "continuation" prompt scoped to the
  working tree. Never assume empty result = no work.
- Resume pattern that works: re-dispatch same task with task_id when the tool
  returned one; otherwise fresh dispatch with "audit the partial work against
  this checklist, complete, and run gates".
- Oracle/tester/docs agents: give them the exact anchors + output format;
  they stall on vague asks.
- Gate discipline per batch: coder self-checks → independent tester → oracle
  (for risky batches) → commit → next batch. Byte-identical mandate on the
  default `standard` blueprint; `tests/parity.rs` must stay byte-identical
  (md5-checked) — never edit pinned tests.
- Repo gotcha: a timed-out `git pull` left the session on `main` once; always
  confirm `git branch --show-current` before committing, and `git merge
  --ff-only origin/dev` after a long session.
